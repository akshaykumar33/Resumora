---
title: Introduction
description: Resumora recovers your users' unfinished work after a crash, a refresh or an expired session, without ever treating stored data as permission to see it.
---

Browsers are unreliable places to do important work. Tabs get discarded, laptops sleep, deploys reload pages and sessions expire mid-form. Resumora is a small runtime that makes sure a user never loses work they've already done.

It records **what the user did** (intents) and **where they'd got to** (checkpoints). It keeps both on the device, and hands them back to your app when the user returns.

## What it is, and what it isn't

| Resumora is                                              | Resumora isn't                                 |
| -------------------------------------------------------- | ---------------------------------------------- |
| A continuity runtime for work in progress                | A database, a cache or a sync engine           |
| Storage-agnostic, through a six-method adapter interface | Tied to IndexedDB, or to any one framework     |
| Strict about tenants: every record is namespaced         | A replacement for authorization on your server |

## Packages

| Package                       | What it does                                       |
| ----------------------------- | -------------------------------------------------- |
| `@resumora/core`              | The runtime. No dependencies and no browser APIs.  |
| `@resumora/storage-indexeddb` | Persistent browser storage on native IndexedDB.    |
| `@resumora/storage-memory`    | In-memory storage with fault injection, for tests. |
