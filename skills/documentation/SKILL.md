# Documentation Skill

## WHEN TO USE
Use when documenting APIs, architecture, guides, or release notes.

## INPUTS
- Code changes and public API signatures.

## PROCESS
1. Provide conceptual overview followed by concrete code examples.
2. Include type signatures and failure modes.
3. Keep prose concise, technical, and precise.

## CHECKS
- [ ] All code snippets are syntactically valid TypeScript.
- [ ] Internal links are verified.

## OUTPUTS
- Markdown documentation files.

## FAILURE CONDITIONS
- Vague generic descriptions without practical code examples.
